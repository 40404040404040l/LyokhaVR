# Перенос проекта на компьютер с Meta Quest 3

Этот архив содержит исходный проект Unity, а не готовый Windows EXE или APK. Сборка для Mac не нужна для запуска из редактора на другом компьютере.

## Открыть проект

1. Полностью распаковать ZIP в папку на локальном диске, например C:\UnityProjects. Не открывать проект внутри архива.
2. В Unity Hub установить Unity Editor **6000.6.7f1** (версия указана в ProjectSettings/ProjectVersion.txt). Для запуска через Windows Editor Android Build Support не нужен.
3. Unity Hub → Projects → Add / Add project from disk → выбрать папку **LyokhaVR**, внутри которой находятся Assets, Packages и ProjectSettings.
4. Открыть проект и дождаться импорта и загрузки пакетов. Интернет при первом открытии нужен. Library, Temp и локальные настройки намеренно не перенесены — Unity создаст их для нового компьютера.

## Quest 3 через Windows-компьютер

1. Установить/открыть Meta Quest Link (в новых инструкциях — Meta Horizon Link): https://www.meta.com/quest/setup/ . Если шлем уже настроен на этом компьютере, повторная установка не нужна.
2. В приложении Link открыть Settings → General → OpenXR Runtime → **Set Meta Quest/Horizon Link as active**. Если уже выбран Meta runtime, повторять не нужно.
3. Подключить Quest 3, надеть его и запустить Quest Link. Сначала убедиться, что в шлеме открылась среда Link и работают оба контроллера.
4. В Unity остановить Play, затем выбрать верхнее меню **LyokhaVR → Launch → Quest via Windows PC (OpenXR)**. Команда включает настоящий OpenXR, профили Touch/Touch Plus, открывает MainMenuVR и запускает игру.
5. В шлеме навести луч контроллера на «Новая игра» и нажать trigger. Настоящий шлем и два контроллера должны управлять игрой; официальный симулятор отключается при активном физическом шлеме.

Это запуск игры на мощности Windows-компьютера через Link. Для автономной установки непосредственно на Quest нужен отдельный Android APK. Он в этот архив не входит. Инструкция Meta: https://developers.meta.com/vr/documentation/unity/unity-link/ . Аппаратный запуск на другом компьютере пока не проверен.

## Обычный режим и симулятор

Остановить Play, затем выбрать:

- **LyokhaVR → Launch → Desktop (keyboard and mouse)** — обычная игра.
- **LyokhaVR → Launch → VR Simulator** — официальный XR Interaction Simulator.

Эти пункты отключают запуск настоящего XR runtime. Между режимами обязательно останавливать Play. Все три сцены каждого режима — главное меню, двор, автозак — включены в проект.

Desktop: Enter/щелчок включает управление; WASD, Shift, мышь; ЛКМ взять/отпустить; E в карман; I/Tab инвентарь; F фонарик; B киоск; Esc курсор.

Quest: левый стик — ходьба; grip — близкий захват; trigger удерживаемой находки — в карман; левая основная кнопка — инвентарь; правая основная — фонарик. В меню луч + trigger.

Симулятор: Tab выбирает устройство, WASD/QE двигает его, G — grip, T — trigger, IJKL — стик. Симуляция движения устройства и игровая ходьба стиком — разные действия.

## Состав и состояние

Включены сцены, скрипты, модели локации и автозака, текстуры, шрифты, звук, 14 уличных фонарей, настройки и точные версии пакетов. Текущие правила описаны в Documentation/CURRENT_BUILD.md.

Файл **SourceFiles/trash.blend** сохранён для дальнейшей замены временного мусора. Его модели ещё не интегрированы в игру: пользователь переключил задачу на перенос и запуск шлема. Оригинал автозака также приложен в SourceFiles, а рабочий FBX уже находится в Assets.

Не включены Git, кэш Library, логи, временные файлы и локальная сборка Mac. Данные аккаунтов и лицензия Unity не переносятся: на новом компьютере используется собственная установка Unity.

Если виден только плоский экран: проверить, что выбран именно пункт Quest via Windows PC, Link-сессия активна и активный OpenXR runtime — Meta Link. Если виртуальные руки не двигаются, сначала проверить контроллеры в среде Link и ошибки Unity Console. Производительность, масштаб и удобство ещё нужно оценить на настоящем Quest 3.
